# Product acceptance catalog v6

Run on Ubuntu with the AppIndicator extension active. Record timestamps, revision,
dependency versions, results, and evidence in an untracked `evidence/` folder.
All nine cases and fifteen required sub-tests must pass for acceptance.

| ID | Prerequisites and repeatable steps | Expected outcome and evidence |
|---|---|---|
| TC01.1 Real measurement | Install, launch, wait at most 65 seconds; run `speedcheck-linux --status`. | Both real Cloudflare speeds > 0; transferred byte counts/durations consistent with decimal Mbps; progress changes; completed state retained. Save status and measurement log. |
| TC02.1 Panel/menu | With a completed test, inspect top-right panel and open its menu. Exercise display selections, Test Now, pause/resume, and login toggle. | Numerical download/upload label visible; latest readings and last/next times shown; menu actions work and changes appear in state/autostart. Save screenshot/accessibility and D-Bus menu evidence. |
| TC02.2 CLI display selection | Run `--display-mode upload`, inspect live state; run legacy `--display both`; repeat while a worker is stalled. | Requested mode appears in state and panel; both spellings reach the running instance without creating another process. Save command timings, preferences and app PID. |
| TC03.1 Automatic schedule | Set `--verification-interval 10`, observe an automatic start without manual action, then `--interval 15`. | Only one test runs; next start time is start + 10 seconds during verification and start + 900 after restore. Save before/after status. Unit checks cover suspend/offline catch-up without replay. |
| TC04.1 Relaunch/persistence | Pause; select upload-only and interval 30; record status. Launch again, then quit/start, finally restore both/15/resumed. | Relaunch keeps the same process; restart restores preferences, cached result and next due; exactly one registered indicator/application. Save process IDs/status before/after and restored state. |
| TC05.1 Failure recovery | With cached success, launch a test, SIGSTOP its worker, and wait for the 60-second watchdog. Inspect status, then use a short verification interval for the next automatic test and restore 15. | UI responds while stalled; worker is killed by deadline; cached results remain with failure indication; future test is scheduled and succeeds. Save timeout and recovery status. Run focused `unittest` checks. |
| TC06.1 Installation/startup | Check desktop/autostart entries, executable path and permissions; run installer twice with preferences changed. Test installer/uninstaller in isolated XDG directories. | Login entry points at the working user executable, toggle persists across reinstall, Quit stops app, uninstall removes only its own files and optionally purges state. Save command output and final entry. |
| TC07.1 Narrow native panel | On GNOME 50, enable SpeedCheck Panel. Inspect native screenshots at 640×800 and 800×800; open SpeedCheck and the clock calendar. Disable/re-enable the helper and restart SpeedCheck. | Clock sits beside Activities on the left; complete download/upload text is readable on the right with no gauge icon or clock overlap; menus work. Disabling restores the prior clock position; re-enabling and app restart restore the text-only layout. Interval stays 15 minutes. Save screenshots, actor rectangles, extension state and final preferences. |
| TC07.2 Resize without clipping | Keep the helper enabled while the native display changes from 640 to 800 pixels wide and back. Inspect the complete panel text and clock/indicator rectangles at each width. | Both numerical speeds and Mbps remain fully visible without an ellipsis; the clock and SpeedCheck never intersect. GNOME uses available panel space instead of squeezing the right side into half the screen. Save screenshots and geometry for all widths. |
| TC08.1 Standalone GNOME startup | With `gnome-shell-headless.service` active, install and validate the app-owned unit and enabled dependency. Start the unit using its boot definition. | One live app/indicator; retained preferences and results; automatic overdue tests work. Save unit/dependency, service, indicator and real-test status. A session replay is not an actual reboot; record that limit. |
| TC08.2 Login toggle on remote desktop | Turn Launch on login off, quit and start the unit. Launch manually, turn login on, quit and start the unit again. | Off removes the login file and skips service startup with no app; on starts one app with cached results and both/15/resumed settings. Save condition results, application bus owner and preferences. |
| TC08.3 Quit, relaunch and cleanup | Quit a service-managed instance, wait beyond its five-second restart delay, then start and relaunch. Repeat install/uninstall in isolated XDG roots with a headless service fixture. | Quit does not respawn; relaunch keeps one PID; install/uninstall manages only the app's unit/link, retains unrelated files, and preserves the login toggle. Leave the real app running. Save process and isolated installation evidence. |
| TC09.1 Sustained sampling | Simulate a fast link with slow short transfers, a consistently slow link, limited time remaining, and an earlier sample faster than the final one. | Larger samples reached where time permits; final completed sample supplies exact decimal Mbps rather than a peak; slow links are not forced into large transfers; payload/deadline bounds preserved. Save focused test output and byte accounting. |
| TC09.2 Live sustained estimate | Install and compare real app runs with bounded independent 32/64 MB downloads, one test at a time. | Successful positive measurements comparable to sustained transfers (within 25% when conditions are stable); retain individual values when variable. One panel indicator, both speeds, 15-minute/resumed preferences at completion. Save status, independent transfers and panel evidence. |
| TC09.3 Measurement failure recovery | With cached success, stall only a live measurement worker and send UI commands. Wait for the 60-second supervisor; allow the next automatic test with a temporary short interval, then restore 15. | UI remains responsive, timed-out worker exits, cached success survives with failure indicated, and a later automatic test succeeds. Save timed states and restored preferences. |
